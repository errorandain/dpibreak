# AGENTS.md — контекст для ИИ-ассистентов (Qwen Code и др.)

> Этот файл автоматически читается при каждом запуске Qwen Code в папке проекта.
> Он задаёт правила работы. Пользователь — не программист: объясняй просто,
> избегай жаргона, предлагай конкретные действия.

## Проект

DPIBreak — Android-приложение для локального обхода DPI (YouTube, Discord, Telegram)
**без root**. Это НЕ VPN: ничего не отправляет на удалённые серверы, IP не меняет,
трафик не шифрует.

Схема: `VpnService (TUN) → hev-socks5-tunnel (tun2socks, C-сабмодуль) → движок byedpi (C-сабмодуль, JNI) → protect()-сокеты → интернет`.

## Стек

- Kotlin 2.0, Jetpack Compose (Material3), minSdk 24, targetSdk 35, JDK 17
- NDK + CMake 3.22.1 (нативная часть: app/src/main/jni/ (ndk-build: byedpi + hev-socks5-tunnel, vendored))
- Версии зависимостей — только в gradle/libs.versions.toml (не дублировать в build-файлах)

## Рабочий процесс

1. Пользователь говорит: «Выполни Задачу N из docs/qwen/TASKS.md».
2. Прочитай задачу сам (файлы доступны). Не хватит контекста — читай docs/ и код.
3. Сначала покажи короткий план (какие файлы создашь/изменишь), дождись «ок», потом код.
4. Одна задача за раз. Не забегай вперёд, не делай рефакторинг «заодно».
5. После кода — сборка: `gradlew.bat assembleDebug` (Windows). Запускай её сам,
   читай вывод, при ошибках исправляй и повторяй до BUILD SUCCESSFUL.
6. Коммит — только после явного согласия пользователя («закоммить»).
   Push — только по прямой команде («запушь»).
7. В конце задачи напомни пользователю: что установить/проверить на телефоне
   (критерии приёмки из TASKS.md).

## Правила кода

- Идиоматичный Kotlin, минимум новых зависимостей.
- НЕ выдумывать API: не уверен в сигнатуре (Compose, VpnService, NDK, JNI) —
  так и скажи и предложи, как проверить.
- Блокирующие вызовы (JNI движка) — только в фоновых потоках/coroutines.
- Комментарии на русском, идентификаторы на английском.
- Маркеры `TODO(Задача N)` для нерешённых частей — сохранять.
- Инварианты (нарушение = баг):
  * исходящие сокеты движка/туннеля — всегда через `VpnService.protect()`;
  * VPN-сервис всегда foreground (тип specialUse);
  * порядок остановки строго обратный порядку запуска;
  * никакой телеметрии и сетевых запросов, кроме пользовательского трафика.
