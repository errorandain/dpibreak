# 🚀 START HERE — путь не-программиста: от нуля до репозитория и первого APK

Этот гайд написан для человека, который **никогда не программировал**. Ваша роль — не писать код, а **управлять процессом**:

| Кто | Что делает |
|---|---|
| **Qwen (ИИ)** | пишет весь код по задачам |
| **GitHub** | хранит проект в облаке (ваша «публичная витрина») |
| **Android Studio** | собирает из кода файл APK (приложение для телефона) |
| **Вы** | менеджер: ставите задачи, проверяете результат, нажимаете кнопки |

Один раз потратите ~1,5–2 часа на настройку — дальше всё по кругу из 4 шагов (Часть 7).

> Инструкция написана для **Windows** (10/11). Понадобится ~15 ГБ свободного места и интернет.

---

## Часть 1. Аккаунт на GitHub (10 минут)

1. Откройте **github.com** → кнопка **Sign up**.
2. Введите: электронную почту → пароль → имя пользователя (латиницей, например `ivan.dpibreak` — оно будет в адресе ваших проектов) → решите капчу.
3. Придёт письмо на почту → откройте ссылку для подтверждения.
4. **Совет:** зайдите в настройки (иконка профиля → **Settings** → **Emails**) и включите **«Keep my email addresses private»** — тогда ваша почта не будет видна в истории изменений.

✅ **Проверка:** вы вошли на github.com под своим именем.

---

## Часть 2. Забрать проект на компьютер (5 минут)

1. В этом чате найдите файл **`dpibreak.zip`** (панель файлов) и **скачайте** его.
2. Создайте папку, например `C:\Projects`.
3. Правый клик по скаченному архиву → **«Извлечь всё...»** → укажите `C:\Projects`.

✅ **Проверка:** у вас есть папка `C:\Projects\dpibreak`, а внутри неё — файлы `README.md`, `settings.gradle.kts`, `gradlew` и папки `app`, `docs`, `gradle`, `.github`.

⚠️ Если внутри появилась вложенность `dpibreak\dpibreak\...` — перенесите содержимое на уровень выше, чтобы путь был именно `C:\Projects\dpibreak`.

---

## Часть 3. Загрузить проект на GitHub через GitHub Desktop (15 минут)

**GitHub Desktop** — кнопочная программа, чтобы заливать файлы в GitHub без командной строки.

1. Зайдите на **desktop.github.com** → **Download for Windows** → установите (Далее-Далее).
2. При первом запуске: **Sign in to GitHub.com** → откроется браузер → **Authorize github** (те же логин/пароль, что на сайте).
3. В программе: меню **File → Add local repository...** → выберите папку `C:\Projects\dpibreak` → **Choose**.
4. Программа скажет, что папка — не репозиторий, и предложит ссылку **«create a repository»** — нажмите её.
5. В окне создания:
   - **Name:** `dpibreak`
   - **Description:** `Локальный обход DPI на Android без root (YouTube, Discord, Telegram)`
   - **Git ignore:** None · **License:** None (всё нужное уже в файлах проекта)
   - **Create repository**
6. Слева в списке **Changes** появятся все файлы. В поле **Summary** напишите: `Первый коммит: каркас проекта` → кнопка **Commit to main**.
7. Теперь сверху — кнопка **Publish repository**:
   - **снимите галку «Keep this code private»**, если хотите, чтобы проект был публичным сразу (вы планировали выложить его);
   - сомневаетесь — оставьте галку (приватный репозиторий), открыть его потом можно в Settings → General → Danger Zone → Change visibility;
   - **Publish**.

✅ **Проверка:** откройте **github.com/ваш-логин/dpibreak** — видны все файлы, а на главной странице README отрисован «красиво» (схема, таблицы, значки).

**Не пугайтесь:** на вкладке **Actions** справа может появиться красная отметка о сборке — на этом этапе это ни на что не влияет (разберём при необходимости). Если зелёная — отлично, CI уже собирает вам APK автоматически.

**Украшение витрины (по желанию, 1 минута):** на странице репозитория нажмите шестерёнку **About** → впишите описание → в поле **Topics** добавьте: `android`, `dpi-bypass`, `youtube`, `discord`, `anti-censorship` → **Save changes**.

## Часть 4. Установка Android Studio (30–60 минут, в основном — скачивание)

1. Зайдите на **developer.android.com/studio** → **Download Android Studio** → установите (все галочки по умолчанию).
2. Первый запуск: **Next → Standard → Accept → Finish**. Студия скачает компоненты SDK (несколько ГБ — это нормально, ждём).
3. Донастройка (если студия сама не предложит): **More Actions → SDK Manager → вкладка SDK Tools** → отметьте:
   - **NDK (Side by side)** — последняя версия;
   - **CMake** — версия 3.22.1 (или ближайшая 3.22.x);
   - → **Apply** → установить.
4. При первом открытии проекта студия сама предложит доустановить недостающее — **всегда соглашайтесь**.

---

## Часть 5. Первая сборка APK — «Задача 0» (10 минут)

1. В Android Studio: **File → Open** → выберите `C:\Projects\dpibreak` → OK.
2. Дождитесь **Gradle Sync** (полоска прогресса внизу; первый раз занимает несколько минут).
3. Меню **Build → Build App Bundle(s) / APK(s) → Build APK(s)**.
4. Внизу справа появится уведомление → нажмите ссылку **locate** — откроется папка с файлом **`app-debug.apk`**.

✅ **Проверка:** файл `app-debug.apk` создан. **Поздравляю — вы только что собраши своё первое Android-приложение!** (Пока это «каркас»: интерфейс с кнопкой, которая ничего не делает. Это нормально — функционал добавляется в Задачах 1–12.)

❌ Если сборка упала: откройте внизу вкладку **Build**, скопируйте **весь красный текст** → вставьте Qwen (или мне, сюда в чат) со словами «вот лог ошибки сборки, исправь». Это стандартный рабочий момент, панике не подлежит 🙂

4'. Зафиксируйте результат: откройте **GitHub Desktop** → у него слева подсветятся изменения (если что-то добавилось/изменилось) → Summary: `Задача 0: первая сборка` → **Commit to main** → **Push origin**.

## Часть 6. Установка APK на Samsung (10 минут)

1. Перекиньте `app-debug.apk` на телефон: USB-кабелем, через Telegram («Избранное»), облако — как удобно.
2. На телефоне откройте файл через «Мои файлы» (проводник). Samsung спросит разрешение на установку из этого источника → **Разрешить** → **Установить**.
3. Откройте приложение **DPIBreak** — увидите экран с кнопкой «Включить обход».

Никакого root не нужно. Пока кнопка — заглушка; живой функционал появится после Задач 1–4.

## Часть 7. Рабочий цикл на каждый день (запомните эту схему)

```
┌─ 1 ──────────────────────────────────────────────────────┐
│  Открыть docs/qwen/MASTER-CONTEXT.md → скопировать текст │
│  → вставить ПЕРВЫМ сообщением в Qwen (новый чат)         │
└──────────────────────────────────────────────────────────┘
                        ↓
┌─ 2 ──────────────────────────────────────────────────────┐
│  Написать Qwen: «Выполни Задачу N из docs/qwen/TASKS.md» │
│  Qwen вернёт список файлов + новый код для каждого       │
└──────────────────────────────────────────────────────────┘
                        ↓
┌─ 3 ──────────────────────────────────────────────────────┐
│  В Android Studio открыть каждый файл → выделить всё     │
│  (Ctrl+A) → вставить новый код (Ctrl+V) → сохранить      │
│  (Ctrl+S). Новые файлы: правый клик на папке → New →     │
│  Kotlin Class/File                                      │
└──────────────────────────────────────────────────────────┘
                        ↓
┌─ 4 ──────────────────────────────────────────────────────┐
│  Build → Build APK(s).                                   │
│   ✅ работает → GitHub Desktop: Commit to main + Push     │
│   ❌ ошибка → красный лог обратно в Qwen: «исправь»       │
│      (и так до победы; 1–2 круга правок — норма)         │
└──────────────────────────────────────────────────────────┘
```

**Правила выживания:**
- **Одна задача — один заход.** Не просите Qwen «сделай сразу всё» — качество упадёт в разы.
- Не переходите к следующей задаче, пока текущая не собралась и не проверена на телефоне.
- Коммитьте часто (после каждого успешного шага) — GitHub хранит всю историю, «сломать навсегда» практически невозможно.
- Задачи 3 и 4 — самые сложные (подключение C-ядра byedpi и туннеля). Заседлаете их — дальше легче.
- При любой непонятной ситуации можно спросить меня (в этом чате) — помогу разобрать лог или подсказать.

## Мини-словарь (чтобы не пугаться слов)

| Термин | Что это по-простому |
|---|---|
| Репозиторий (repo) | Папка проекта на GitHub с историей всех изменений |
| Коммит (commit) | Сохранённый «снимок» изменений с подписью |
| Push | Отправка коммитов с компьютера на GitHub |
| Pull/Clone | Скачивание репозитория с GitHub на компьютер |
| APK | Файл-установщик Android-приложения (как .exe у Windows) |
| Gradle | Сборщик: превращает код в APK. Wrapper (`gradlew`) — его «загрузчик» |
| SDK | Набор инструментов Android для сборки приложений |
| NDK | Надстройка SDK для сборки C-кода (нужна для движка byedpi) |
| Ветка main | Основная линия проекта (пока единственная — просто запомните) |
| CI / Actions | Автосборка на GitHub при каждом push (наш `.github/workflows`) |
| JNI | Мост между Java/Kotlin и C-кодом движка |

## Если что-то пошло не так (частые ситуации)

| Симптом | Что делать |
|---|---|
| Письмо от GitHub не пришло | Проверьте папку «Спам»; подождите 5 минут; запросите повторно на github.com |
| GitHub Desktop «не видит» папку | Убедитесь, что выбрали именно `C:\Projects\dpibreak` (с файлом `settings.gradle.kts` внутри) |
| Студия просит «install missing components» | Соглашайтесь — это нормальная доустановка SDK/NDK |
| «SDK location not found» | В папке проекта создайте файл `local.properties` со строкой `sdk.dir=C\:\\Users\\ИМЯ\\AppData\\Local\\Android\\Sdk` (или File → Project Structure → SDK Location) |
| Сборка упала | Весь красный текст из вкладки Build → в Qwen «исправь» (или мне в чат) |
| APK не ставится («приложение не установлено») | Удалите старую версию DPIBreak с телефона и поставьте заново |
| Actions на GitHub красные | Не критично для работы; разберём на Задаче 11 (релизная сборка) |
